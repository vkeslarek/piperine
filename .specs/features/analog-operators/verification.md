**(a) F2, the kept golden line.** The record is now there (tasks.md rule, C61, design.md D18), so the parity-rule breach is closed. The golden line itself is required by AO-10 AC 2 (C57): the nature's flow `abstol` must reach the branch unknown, and the plan carries it on the private flow pin, which the transpile golden prints. D18's claim "no run value moves" holds only at the default session `abstol`. The Verifier's probe (throwaway `piperine-api` test, removed): a design with an `Electrical` source, `Tolerances { abstol: 1e-6 }`, `Bound::tighten`, a 5e-10 residual on the source's branch row is **rejected**, because `tighten` writes 1e-12 into `branch_abstol_overrides` (bind.rs `tighten`, `map.extend`) and `abstol_for` uses the override in place of the session value. So `--abstol` no longer reaches the flow unknown of any potential branch whose ends carry a nature with a flow, i.e. every voltage source of an MSL design, looser or tighter alike. §17.1 rules 1 and 2 say the tolerance is the nature's, which the code follows; the Book's key table says `abstol` is "the absolute tolerance of a branch flow" and `vntol` is one "a nature's own `abstol` can tighten" (a minimum), which the code does not follow for branches (nor, before this feature, for nodes: `vntol_for` replaces too). Finding 12.

**(b) F3, the deferred settle phase.** Holds for what it fixes: `JumpRetake` is armed by `boundary` or `settle_boundary` and by the operating point's held settle commit; an instant that may be retaken runs its rounds without the settle phase and settles once after the last round; `absorb_settle` keeps the settle commits of that one phase. The two new tests would fail without the fix (settle stamps strictly increase, 4 V reached after a second round; the settle-commit step retakes). Two divergences remain:
- The deferred settle phase runs as a second `run_instant` at the same tick, which starts a fresh microstep loop at `n = 0` (piperine-digital-solver instant.rs:148-150: no suspended instant), goes quiet at `n = 0` and calls `settle_phase(at, 0)`, so its records and commits are stamped `(t, 0)`; §19's Resolution (part_vi_io.md:89-90) stamps them `(t, last)`, the instant's last microstep. This happens on every instant whose step read a jump and fired a crossing, retaken or not (the buck at each switching edge). The same holds for a retake round: its new crossings are fired at `(t, 0)` of a fresh loop (`DiscreteSide::fire` commits at microstep 0, engine.rs:325), where §15.2 rule 4 says "the next microstep of `t`". Neither `Record` nor `Observation` carries a microstep today, so no output shows it, but the stamps and the microstep numbering inside the engine are not the spec's. Finding 13.
- Part V §15.2 rule 6 (part_v_execution.md, rule 6): "The first step after the operating point reads no jump and keeps its BDF2 stage." When the operating point holds a settle commit, `operating_point.rs:67` delivers it with `Restart::Integrator`, `device_deliver` sets `sets_just_applied`, so the first step is `JumpPosition::Reads` (backward Euler second stage) and `JumpRetake::new(exempt_next)` arms the retake. The code follows S3 (that step reads a change due before its solve); the spec sentence is false in that case. Finding 14.

**(c) `Box::leak(Box::new(module::<X>(..)))` in the partials checks.** The guard (`crates/piperine-solver/tests/abi_devices.rs` `every_hand_written_device_is_in_a_partials_check`) protects one thing: every hand-written `impl Device for X` of a target has its functions run through the partials verifier in that target. It recognises a check by the device its module argument builds (`module::<X>(`) or by a free `fn f() -> &'static Module` helper; it does not recognise the new associated `X::module()`. The leaked inline module is built from the same `Device` impl the circuits use (`X::module()` is `module::<X>(..)` behind a `OnceLock`), so the verifier checks the very code under test and the guard still fails if a check is removed: the intent holds, it is not an evasion (the inline form is what makes the guard match, not what avoids it). The cost is a second construction per device, written twice, and a leaked `Module` per test run. The honest form is to teach `module_helpers`/`checked_devices` the `X::module()` associated function and pass `Gate::module()`; recorded as part of Finding 15, not as a breach.

**Records.** `GAPS.md` H2, H3 and U7 and `ROADMAP.md` item 4 describe what B1 to B3 deliver; the Book's key table has the `noise`, `tnom` and `simparam` rows (content.html:5879-5909), held by `book` `the_chapter_shows_the_session_options`.
