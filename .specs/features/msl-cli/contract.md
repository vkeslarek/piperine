# msl-cli: the contract with the merged msl-digital

**Task**: T1. **Read at**: `feature/msl-cli` 47b4f3d7, rebased on `main` 94626f88 (which holds the merged `msl-digital`, 67 tasks).
**Verdict**: no difference needs a redesign, and one defect outside this feature's crates blocks the RC example's records (D12, reported to the orchestrator before T2). A record names its own `emit!` site and the buck runs closed loop from MSL (DIG-16 merged). Every bench form the RC example needs runs on the Rust backend, **provided some body of the design holds a carrier**: a design whose reactions hold no carrier is compiled with the analog runtime only and its reactions never run, silently (D12). Eleven names or shapes differ from what design.md took from the `msl-digital` design text; each is resolved below by a rename, a dependency or a key, and the task that absorbs it is named. One finding changes the run request: a long mixed transient must not keep every accepted step, and the solver's only bound without a solver edit is `record_from`, so a `transient` run reads `from` (D10).

Gate evidence: `cargo test -p piperine-parity --test buck_records` (4 passed) and `--test buck_closed_loop` (4 passed, 784 s wall, 778.2 s of it the 600 µs transient) on this tree, and a scratch run (never committed) of the Book's RC project, chapter 1, on the Rust backend (SCRATCH).

## How a `Record` observation is tied to its `emit!` site

The record names its site. `ObservationKind::Record { site: Some((reaction, statement)), bytes }` arrives with `Observation::path` = `<instance path>.<stream>`; `Ir::record_at(&o.path, reaction, statement)` gives the instance and the `RecordSite` (stream name and the site's text fields, in source order); the value fields are read from `bytes` through `RecordLayout::of(stream)`, `stream` being `instance.body().streams()` by the site's stream name. No pairing with a `Commit` by order. Shown by `crates/piperine-parity/tests/buck_records.rs` (`records_of_two_reactions_are_told_apart`, `records_of_two_reactions_at_different_statements_keep_their_texts`: two reactions of one instant, sites at statement 0 of each and at statements 0 and 1, each record keeps its own text) and by `buck_closed_loop.rs::no_shoot_through_during_the_start` (120 000 `checks` records of a child instance, each decoded on its own).

## The top

`Elaborator::run(top)` elaborates a top whose ports are all discrete: each port becomes a net of the top that nothing writes, unknown unless initialised (`crates/piperine-lang/src/elab/elaborator.rs:135`, DIG-09 AC 5); a continuous port is `P0001`. `crates/piperine-parity/tests/buck_whole.rs` runs `Buck` (discrete ports `en`, `sp_wr`, ...) as the top this way. The spec's default rule ("the one module without ports") therefore never picks `Buck`; the `idle` run names it with `top = "Buck"` (T21), which CLI-05 AC 1 already allows.

Merged. `crates/piperine-parity/tests/buck_closed_loop.rs` (4 tests over one run: `the_buck_starts_and_reaches_regulate`, `power_good_is_high_and_no_fault_is_latched`, `the_output_settles_within_10_mv_of_0v8`, `no_shoot_through_during_the_start`) runs `LoopBench` of `tests/buck/closed_loop.msl` over `examples/buck/src` for 600 µs: the reference ends at 128, mode goes `Off`, `SoftStart`, `Regulate`. ## Differences and how each is resolved

- **D1 - `Record` carries its site.** `Record { site: Option<(u32, u32)>, bytes }`, not bytes and a path alone (design Risks row 2). The risk is void: a record decodes on its own. `site == None` (a relaxed field that moved, abi.md §9 D1) has no site, so no text fields: `Streams::decode` gives it with the stream from the pin path and the value fields from the bytes, and no text field. **T14.**
- **D2 - one decoder.** design `Streams::of(ir)` ("every stream of every instance with its layout and its sites") is `Ir::record_at` plus `RecordLayout::of`: `Streams` keeps the per-stream `RecordLayout` (by pin path) and the filter of CLI-12, and decodes with `record_at`. It never pairs a record with a commit. **T14, T27.**
- **D3 - `piperine-api` depends on `piperine-plan`** for `RecordLayout` and `CarrierLayout` (the decoding of a record's bytes and of a discrete net's bytes in a table). Added to its manifest by the first task that decodes bytes. **T12 (discrete cells), T14 (records).**
- **D4 - the interpreter's refusal says "(use the compiled backend)", not `--backend rust`.** `piperine-interp` is not edited. The API's `Failure::Backend` for an interpreter refusal holds the entries' text and adds the hint `--backend rust`. **T10.**
- **D5 - `Report::hit` is `Report::cache_hit: bool`.** `Session::built()` reads it. **T10, T31.**
- **D6 - a discrete net is found with `Ir::net_at`**, the third lookup beside `node_at` and `instance_at`; in a transient its value at a step is `TransientStep::digital_named(path)` (the net's layout bytes, `CarrierLayout`). **T11, T12, T13.**
- **D7 - records arrive in the operating point too.** `Observation::analysis` is `OperatingPoint` for a record of the initial solution of a transient (`START` reactions, an `above` already positive). CLI-06 AC 7 prints every record line of an analysis before its table, and a transient's operating point is part of it: the records of both are printed, in delivery order. **T14.**
- **D8 - a bench's top with discrete ports** is elaborated (section "The top"); the default choice still takes the one module without ports. **T10, T21.**
- **D9 - the RC example is the Book's.** The Book (chapter 1, landed on `main`) already prints the RC project: 1 kΩ and 1 nF (τ = 1 µs), output node `vout` (`out` is a keyword), `Monitor` on `cross(v(a) - level)` calling `emit!("trip", v = v(a))` and `require("crossed_upward", ...)`, runs `op` and `step` (`stop = 5e-6`, `print_step = 1e-6`: 6 rows). T6 adopts it as written instead of the 1.5915494309189535 nF of its task text: the record's time is the record line's own `@<time>`, so the `emit!` carries the voltage only. **T6, T34, T36.**
- **D10 - a long mixed transient must not keep every accepted step.** The solver keeps one `TransientStep` per accepted step with a re-entry state (GAPS §6, N2: about 58 KB each; the whole buck takes about 45 000 steps per 40 µs). The one bound the solver offers without a solver edit is `TransientAnalysisOptions::record_from`: steps before it are integrated and not kept; the sink still delivers every record. A `transient` run therefore reads the key `from` (flag `--from`, already a key of `dc` and `ac`): the first time the result keeps, ngspice's `tstart`; optional, 0 by default, `0 <= from < stop` else `P0010`. The print grid starts at the first multiple of `print_step` at or after `from`; a plot draws from `from`. The record lines are not bounded by it. The buck's `startup` run sets `from` so that only its last microseconds are kept. CLI-03 AC 1's list of keys does not change; design "Which keys an analysis reads" gains `from` for `transient`. **T7 (the key), T13 (`record_from`), T21 (`startup`), T25 (the grid), T42 (the plot), T36 (the Book's key table).**
- **D11 - `Settings::resolve`** takes a lookup function, so a test passes `PIPERINE_CACHE_DIR` without setting a variable of its own process; the e2e tests set it on the child, as planned. **T10.**
- **D12 - defect (blocks T18's RC records; not fixable here).** `Transpiler::digital()` (`crates/piperine-transpile/src/lib.rs:87`) is `bodies().any(|b| !b.carriers().is_empty())`, and `compile` picks the runtime by it (`compile.rs:38`): a design whose reactions, events and record streams sit in bodies with no carrier gets the analog-only runtime, and its reactions never run, with no error. The Book's RC bench is exactly that (`Monitor` has no `signal`). `piperine-transpile` is not edited by this feature. Fix: `digital()` also counts reactions, events and streams (one line plus a test in `piperine-transpile`), as its own task or by the orchestrator. Until then `examples/rc` (T6) keeps the Book's text, which resolves and type-checks; T18's `trip` record waits on the fix. A workaround in the example (a dummy carrier) would hide the bug and is not taken.
- **D13 - record order inside one instant is the sink's, not the statements'.** At the crossing the solver delivered `checks` (statement 2) before `trip` (statement 1) of the same reaction and instant. CLI-06 AC 3 prints sink order, so the Book's `run step` block (trip, then checks) may differ from the binary: T36 holds the Book to the binary, the assertion is not changed. **T14, T36.**
- **D14 - `above` over a body that emits is `P0001`.** The Book's `benches/delayed.msl` (`on above(...) { emit!(...) }`) does not elaborate; a bench uses `cross`. **T36.**
