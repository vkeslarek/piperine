## Judged areas

- **Stdlib items against §22, with closed-form oracles.** `source_stdlib_generic.rs` computes every expected value in Rust from the rule it cites (`Section22`, `MonitorSchedule`, `Integrals`, `Laplace`, `Difference`, `TableModel`), never from the model. `since` follows §22.1.8 rules 2 and 3 (the first commit at (0, 0) is a change; T106's reading of the text is right, design-e.md's table was not). `MinPulse`, `Setup`, `Hold`, `Stable` are exact per instant at `u8` and at an enum, with both outcomes present. `inertial`'s oracle (cancel when the next change precedes delivery; emit only a change of the held value) is the §22.5.8 filter. `Short` holds 3 V and 1 mA to 1e-6/1e-9 over two natures. `noise_table` holds 1e-9 relative at a table point, between points (1e4 Hz, linear in f) and past the last (constant), which is `1C`. Holds.
- **`idtmod` across wraps.** `wrapped(at)` is `offset + (rate·t − offset).rem_euclid(modulus)`; over 12 us at 0.3 MV/s the integral wraps four times (at 1.67, 5, 8.33, 11.67 us) and the reads at k + 0.5 us sit away from them; the `SPEC_DEVIATION` guard is gone and S9 left `GAPS.md`. Holds.
- **`laplace_*`/`zi_*` numerics.** Probed beyond the checks: a biproper `laplace_zp::<1, 1>` (zero at −2M), a high-pass `laplace_nd::<2, 2>`, a third-order `laplace_zp::<0, 3>` with a complex pair, a second-order `zi_zp::<0, 2>` with poles 0.5 ± 0.3j, and `zi_nd::<3, 2>`. All match the closed form or the Rust difference equation (laplace worst 3.3e-7 first order, 3.1e-6 third order; zi exact to 1e-6). The implementation is right; the laplace test's tolerance is not (finding 3).
- **The 5e-3 laplace tolerance**: written inline in the test (`source_stdlib_generic.rs:429,432`), not in a contract. No project rule requires a contract for a closed-form oracle (`ToleranceContract` is the ngspice oracles' place), so the location is acceptable; the value is not (finding 3).
- **`inertial` only at a type with `Default`.** Part I §3.3.4 says `bool`, `UInt`, `Int`, `Float` and `str` do not implement `Default` "on purpose", and §22.5.8 bounds `T: Repr + Default` (rule 7). `inertial_at_a_type_without_default_is_refused` pins `E0187` naming `Default`. The AFK default is right and approved. Note (no finding): §22.5.8 rule 4, "It delays a `Bit` or the drive of a resolved net alike", reads as if `Bit<bool>` were allowed; it means the carrier `Bit<T>`. A wording question for `spec-closure`, not this phase.
- **T110a, composite params at a hoisted placement.** Arrays, nested arrays, a tuple, a struct, a whole array passed to a `fn`, a given value read through two hoisted levels (`Outer { d }` → `Inner { c: d }`) and one built from a caller's generation index all fold and print the right constant. An `Option` anywhere in the param crashes (finding 2).
- **T118, generation in a hoisted body.** Probed a hoisted module whose generation places another hoisted module reading the loop variable, and a hoisted generation inside a hoisted generation with a param-dependent trip count (`Inner { n: j + 2 }` in `for j in 0..2`): every element and name (`b.i[1].s[2]`) is right. Holds.
- **T119/T121, arrays of templates.** A written index, a param-driven index, a generation index, a module with a result through an element, a param array overridden from the parent, and an out-of-range index (`E0104` naming "the element 2 of an array of 2 templates") hold. `[Scale { r: 7.0 }; 2]` is a named `P0001` (loud; acceptable). The host refusal `E0802` through `is_template_param` holds. Two defects: a template that carries a composite param crashes (finding 1), and the array param keys its body by the arena id of the aggregate (finding 4).

## Own examples (HEAD 53ce664fb)

- `let t = Inner { c: [3.0, 9.0] }; let b = t(1.0);` (`Inner` has a result and a param `c: [f64; 2]`): **panic** `index out of bounds: the len is 0 but the index is 0` at `crates/piperine-ir/src/build.rs:151` (`aggregate_at`), through `hoisted_params` → `bind_param` → `imported_tree`. The same with `const T: Inner = Inner { c: [3.0, 9.0] }`: same panic. The same for a module **without** a result, `let t = Cell { cs: [3.0, 4.0] }; t(x)`: same panic through `place_instance` → `bind_params` (finding 1).
- `module Inner(x: f64) -> f64 { c: Option<f64> = Some(2.0); x * c.unwrap_or(5.0) }` placed as `Inner(1.0)`: **panic** "the composite constant agg2 has no constant form at its type" at `crates/piperine-lang/src/elab/lower.rs:839`. Also `c: [Option<f64>; 2]` read as `c[0].unwrap_or(5.0)` (default and given), `c: (f64, Option<f64>)`, and `[Option<f64>; 2]` passed whole to a `fn`. The same `[Option<f64>; 2]` param in a module without a result elaborates (finding 2).
- `laplace.msl` as committed: worst error 3.5e-7 (first order, four spellings) and 3.2e-6 (second order) at the 5 ns step; 1.6e-5 at 50 ns (finding 3).
- `Mid(x) { pair: [Cell { cs: 5.0 }, Cell { cs: 6.0 }] }` placed twice: four bodies `Mid~pair=agg1..agg4`, two of them dead; the child `m` names `Mid~pair=agg2` while the instance `Top.m` is `Mid~pair=agg1`. A single template param placed twice with equal values is one body `Mid~one=1` (finding 4).
- `module Mid<C: Fn(f64) -> f64>(in u: Bit<f64>) { s: C; ... let a = s(5.0); }` placed with `{ s: Scale { r: 9.0 } }`: `P0001` "a call the type checker did not resolve" plus a cascade `P0001` "a node argument that is not a name"; no `GAPS.md` row (finding 5).
- Holding: `s: Scale = Scale { r: 3.0 }; s(5.0)` → `5.0 * 3.0`; overridden by the parent → `5.0 * 9.0`; `fs[k](1.0)` with `k` a param → `1.0 * 8.0`; template arrays inside a hoisted module → `2.0 + 3.0`; a composite given through two hoisted levels → `[5.0, 6.0][1]`; from a generation index → `[k, k + 10][1]` per `k`; `Option` module result read in a definition, a `match` and an `if let` in a reaction; nested generation in nested hoisted frames; `[[f64; 2]; 2]`, a struct and a whole array as hoisted params.
