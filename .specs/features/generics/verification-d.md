## Round 5 (882b275c8)

- **Findings 17 to 19**: closed (column `Closed`).
- **`E0240` to `E0413` for `i(y) +>` on a flowless nature** (322e6c00c): `E0413` is the spec's code. Part IV §11 rule 11 lists `E0413` for "a flow contribution on a nature without `flow`", and part II lists `E0240` for "a probe or contribution whose two nodes have different natures", which a one-node contribution is not. The alias and the direct form now give the same code (C115).
- **Parentheses** (892127416): `v((y))`, `v((c0.sn))` and `i((x)) +> ..` lower to the named node's probe or branch. This is general: parentheses are transparent for every node argument.
- **A node chosen by an expression is `E0133`** (9c93f7c5f; part I §1.4.7 amended, AFK pending user review): an `if`, a `match` or a block whose result is a node, as a `let` in `analog` or in a module body. The rule is consistent with "a node is hardware, never a value", and the message tells the user to name the node itself. For the user's review: it also refuses forms that elaboration could fold, such as `let y = if sel { x } else { p };` over a param and the trivial `let y = { x };`. A conditional statement (`if sel { .. v(x) .. } else { .. v(p) .. }`) runs. The `E0133` row keeps its phase column "elaboration" although the checker raises the new case; the other checker-raised rows read the same, so this is not a finding.

## Round 4 (e1a271bea)

- **Finding 16**: closed by 11ee4a8d8 (column `Closed`). The fix is general, not a special case. The checker takes the access's quantity from the nature of whatever node the operand's type names (`Ty::Node(nature)`), for any nature and any access name. The elaborator binds every `let` whose type is a node as a handle, as it binds an inlined function's handle param. Nothing in either is keyed to templates, a nature or a name.
- **Other uses through such a `let`**: a flow contribution `i(y) +> ..`, `potential(y) +> ..`, a two-node probe, `ddt` of a probe, a chain of `let`s and a `Thermal` node behave. A flow probe read as a value is the pre-existing L73-family `P0001`. Using the `let` as a number is `E0180` naming the node's nature. Findings 17 and 18 are the two uses that do not behave.
- **Not findings**: `v((y))` and `v((c0.sn))` are `P0001` "a node argument that is not a name", as `v((x))` on a module's own node is. This is the general elaboration refusal (`elab/analog.rs:370`), not one the fix introduced. Before 11ee4a8d8 the checker peeled parentheses for a template read. Whether `v((c0.sn))` elaborated then was not probed. `let y = if v(p) > 0.0 { x } else { p };` reaches the same elaboration `P0001`. Before the fix it was the "several natures" `P0001`, so it is still refused loud. A node chosen at run time is a spec question, not this phase's.
